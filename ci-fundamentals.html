Program transformation · Agile delivery

CI Fundamentals transformation

I replaced an outdated, low-completion course with a five-course, practice-based learning path whose modular format was then adopted across the department.

Delivery model
Two-week sprints
Role
End-to-end program and production owner
Scope
Five courses with video, labs, and realistic examples
Completion
29% to 68%

The challenge

Completion was below 30%, the content was outdated, and learner feedback repeatedly asked for more relevant examples and video-based instruction instead of embedded documentation. Waiting until quarter-end to publish improvements also delayed value for customers.

Program strategy

I decomposed the experience into five focused courses and planned an incremental release cadence. Each course combined concise video instruction, realistic examples, hands-on labs, and technical review checkpoints.

Leadership and execution

  • Owned the roadmap, curriculum, production workflow, publishing, and measurement end to end.
  • Managed the backlog and sprint cadence in GitLab.
  • Planned, recorded, edited, and published the program content.
  • Partnered with subject-matter experts for technical accuracy reviews.
  • Released improvements every two weeks instead of waiting for a quarterly launch.
  • Established the modular learning-path model used to convert the department’s remaining courses.

Measurement and iteration

I used customer feedback and completion data to set priorities, created an executable roadmap, established technical quality gates, and released improvements through a two-week agile operating cadence.

Outcome

The five-course learning path more than doubled completion from 29% to 68%, while the sprint-based model put useful content into customers’ hands sooner. Its modular format was subsequently replicated across the department, converting all courses to the learning-path model.
